# Verification cases: Profiles and note groups

Status: maintained reusable case definitions. Automated counterparts and native
checks now exist; their execution results and remaining manual checks live in
[execution evidence](execution-2026-10-10.md), not in these scenarios. These definitions
follow the playbook's Test Case Standards referenced in [review.md](review.md#workflow).

## Shared Execution Contract

Owner: Pinleaf maintainer. Sources: [specification](spec.md),
[plan](plan.md), [tasks](tasks.md) and [migration contract](contracts/migration-v5.json).

Preconditions common to every case: use the feature build under test and an
independent temporary data directory/database. Use synthetic data only. Desktop
execution requires GTK 4/libadwaita on the supported target and an isolated test
application/session bus or dedicated desktop session, so actions cannot be sent
to the user's already-running Pinleaf. `XDG_DATA_HOME` alone does not distinguish
application identity. Record the source revision and relevant session/locale.

Reproducible data baseline:

| Data | Value or generation rule |
| --- | --- |
| Clock | Fixed creation time `2026-10-10T12:00:00+00:00`; advance one minute per note |
| IDs | Deterministic sequence generated by injected factories; retain a map of IDs by labels below |
| Profiles/groups | Seventh: General, LGPD, Agenda; Freelancer: General, Empresa X - DevOps; Pessoal: General, Financeiro, Dieta |
| N1 | LGPD, open, `Checklist LGPD` |
| N2 | LGPD, hidden, `Revisão LGPD` |
| N3 | Agenda, hidden, `Reunião semanal` |
| N4 | Empresa X - DevOps, open, `Revisar deploy` |
| N5 | Financeiro, open, `Planejar Café mensal` |
| N6 | Dieta, open, `Preparar refeições` |
| N7 | LGPD, already soft-deleted, `Café excluído`, fixed deletion time after creation |
| Default note state | Supported color, 320x280 size and known appearance; migration fixtures additionally vary every persisted field and include null coordinates/appearance |
| Initial active context | Seventh / LGPD unless the case overrides it |
| Remembered contexts | Seventh / LGPD, Freelancer / Empresa X - DevOps, Pessoal / Financeiro |

Legacy fixtures contain the same note states/values without memberships; only
columns available in their actual source schema exist. Compare original values
directly, not through a reader that materializes appearance defaults. Each case
starts from a fresh fixture; it never depends on earlier cases.

Scale fixtures for T16 use the same deterministic IDs/clock. For normal startup,
create 100 notes in initial General. For the larger library, create three profiles
with ten groups each (General plus G01..G09), distribute 1,000 notes round-robin
over those 30 groups and use exactly 128-code-point synthetic content per note.
In both datasets, every fourth note is hidden and the remainder open; exclude
deleted notes from this timing baseline. Record measurement start/end definitions
and the active group's displayed-window count with each timing.

Common cleanup for every case: close the isolated app and database connections,
cancel fake schedulers, and remove the case's temporary data, backups and recovery
sets after retaining required evidence. Never remove the user's note directory.

Execution results belong in a separate record with case/revision, build revision,
executor/time, environment, result, actual behavior, concise evidence and defects.
Use not run/skipped when a session or accessibility tool is unavailable. Do not
mark candidate automation as automated until its assertions run in the intended
test path. Case data tables select representative variants, not a mandatory full
Cartesian product.

## TC-CTX-001

| Field | Value |
| --- | --- |
| Title | Preserve every retained note during organization migration |
| Traceability | [AC-10, AC-11](spec.md#acceptance-examples); CTX-01, CTX-02; migration contract |
| Risk | Critical: lost content, hidden-state changes or orphaned notes |
| Classification | Storage/integration, migration and data integrity |
| Automation | Automated migration/backup tests |

Objective: verify that successful migration only adds valid initial membership.

Preconditions: a valid legacy fixture and writable private backup location.
Test data: run source versions 1, 2, 3 and 4; retain all original note values and
settings before execution. Include open, hidden, deleted and empty notes.

```text
Given the isolated source library contains the recorded legacy values
When schema 5 migration completes
Then every retained note belongs to initial Personal/Pessoal -> General/Geral
And original IDs, values, row counts, timestamps and settings are unchanged
And a validated source-version snapshot exists and repeat startup does not reseed
```

Cleanup: common cleanup, including generated snapshots.

## TC-CTX-002

| Field | Value |
| --- | --- |
| Title | Keep the original library after an upgrade failure |
| Traceability | [AC-10](spec.md#acceptance-examples); migration failure/backup contract |
| Risk | Critical: a partially upgraded database becomes unusable |
| Classification | Storage/integration, reliability and recovery |
| Automation | Automated migration/backup fault tests |

Objective: verify the upgrade's preflight and rollback boundary.

Preconditions: a fresh source fixture per variant; capture original schema/data.
Test data: representative failures in snapshot creation/validation, table rebuild,
note copy and final version update. Include process interruption before commit;
open a fresh connection afterwards so SQLite recovery can complete.

```text
Given a supported legacy library and the selected injected failure
When the application attempts the organization upgrade
Then the original schema version and logical data remain readable and unchanged
And no partial membership/context upgrade is retained
And startup does not open an empty replacement library and reports the failure
```

Cleanup: common cleanup; retain failure stage and recovery output as evidence.

## TC-CTX-003

| Field | Value |
| --- | --- |
| Title | Restore the validated snapshot for the older reader |
| Traceability | [Rollout and Operations](spec.md#rollout-and-operations); migration rollback contract |
| Risk | Critical: downgrade destroys the only copy of newer work |
| Classification | System/operational recovery and compatibility |
| Automation | Reproducible drill using the previous binary's migrator |

Objective: prove the documented restore path and its snapshot boundary.

Preconditions: successful isolated migration, validated source snapshot, a
pre-upgrade reader/binary, and no app process holding the case database open.
Test data: record original values, then add a distinguishable `After snapshot`
note to schema 5. Preserve the current database and any sidecars as a recovery set.

```text
Given the older reader refuses schema 5 without mutating it
When the stopped test app's database is replaced by its validated source snapshot
Then the older reader opens the original schema and original note values
And After snapshot is absent from the restored library
And that newer work remains available in the separately preserved recovery set
```

Cleanup: common cleanup after recording both recovery-set and restored values.

## TC-CTX-004

| Field | Value |
| --- | --- |
| Title | Keep hidden notes hidden when cycling groups and profiles |
| Traceability | [AC-01, AC-02, AC-04](spec.md#acceptance-examples); CTX-05, CTX-06, CTX-07 |
| Risk | High: switching context opens private distractions or hides wanted notes |
| Classification | Controller/integration and system, functional lifecycle |
| Automation | Automated fake-window and GTK tests; manual desktop pass also required |

Objective: verify that context activation is independent of individual visibility.

Preconditions: shared baseline; inspect stored open flags before the scenario.
Test data: cycle Agenda, Pessoal, then Seventh; use their remembered groups. In a
separate fresh-fixture variant, explicitly Activate and open hidden Agenda N3.

```text
Given LGPD is active with N1 open and N2 hidden
When the user cycles contexts and returns to LGPD
Then only each selected group's individually open notes appear
And N2 stays hidden/struck through and last-used groups are restored
And the explicit-open variant opens only N3 without reviving other hidden notes
```

Cleanup: common cleanup; record controller assertions and desktop session separately.

## TC-CTX-005

| Field | Value |
| --- | --- |
| Title | Retain the prior context and pending text after a failed transition |
| Traceability | [AC-05, AC-16](spec.md#acceptance-examples); CTX-09, DEL-07 |
| Risk | Critical: unsaved text is lost during context change or disposal |
| Classification | Controller/integration, reliability and data integrity |
| Automation | Automated fault injection; manual visible-error/retry check |

Objective: verify failed context-changing commands preserve editors and organization.

Preconditions: shared baseline with unsaved `Pending draft` appended to N1.
Test data: inject flush, geometry-save, destination-preparation and SQL/commit
failures. Select representative commands: activate Agenda, delete LGPD with
transfer, and delete Seventh with Delete all and Pessoal as replacement.

```text
Given the command has not crossed the durable commit boundary
When the selected required step fails
Then LGPD remains active and N1 retains its latest text in an available editor
And membership, container deletion and individual open flags remain unchanged
And an actionable error permits retry, without presenting a partial new context
```

Successfully flushed text in other notes may remain saved; it is not an
organizational rollback failure. Cleanup: common cleanup and reset injected faults.

## TC-CTX-006

| Field | Value |
| --- | --- |
| Title | Move a note without changing active context or individual visibility |
| Traceability | [AC-06, AC-07](spec.md#acceptance-examples); FLOW-03, FLOW-04 |
| Risk | High: movement loses metadata or accidentally opens hidden notes |
| Classification | Service/controller/dialog integration, state transitions |
| Automation | Automated service/controller/dialog tests; desktop spot check |

Objective: verify one-note movement independently of context activation.

Preconditions: fresh shared baseline for each variant.
Test data: move open N1 to Freelancer / Empresa X - DevOps; separately activate
Pessoal / Financeiro and move hidden N2 into it. Record all original note fields.

```text
Given a source note and an explicitly selected different live destination
When Move is confirmed
Then membership changes while the active context and original note state remain
And an open note leaving the active group leaves its desktop until the destination activates
And a hidden note moved into the active group remains hidden until explicitly opened
```

Cleanup: common cleanup.

## TC-CTX-007

| Field | Value |
| --- | --- |
| Title | Transfer a removed container's notes without losing their states |

| Risk | Critical: bulk transfer loses notes or leaves an invalid active context |
| Classification | Service/controller/system, data integrity and lifecycle |
| Automation | Disposal/controller tests; manual summary/desktop check |

Objective: verify container transfer, retention and context repair in one operation.

Preconditions: shared baseline; confirm source count includes N2 and excludes N7.

fresh-fixture profile variant deletes Seventh with the same destination.

```text

And note values/open/deleted states remain intact and source containers disappear

```

No source groups are recreated at the destination. Execute failure variants under
TC-CTX-005. Cleanup: common cleanup.

## TC-CTX-012

| Field | Value |

| Title | Browse and cancel with keyboard focus and accessible state intact |
| Traceability | [AC-03](spec.md#acceptance-examples); UX-03, UX-07; accessibility attributes |
| Risk | High: keyboard or assistive-technology users cannot navigate safely |
| Classification | System, accessibility and usability regression |
| Automation | Manual keyboard/screen-reader; automated focused widget assertions |

Objective: verify browsing/dialog cancellation can be completed without unintended activation.

Preconditions: shared desktop baseline, keyboard and screen reader available;
record GTK/libadwaita version, session, theme and actual window dimensions.
Test data: add an inactive group with an 80-code-point name (`G` repeated 80
times); use the smallest supported panel width. Repeat theme/locale variants
only where they materially affect labels or visibility.

```text
Given LGPD is active and the inactive group/header controls are keyboard reachable
When the user expands the inactive group, opens Rename and cancels using the keyboard
Then LGPD and its desktop remain active and new-note destination remains LGPD
And focus returns to the invoking control without losing the expansion state
And active, hidden and expanded states plus the full long name are announced accessibly
```

Check Ctrl+F selection/Escape clearing under the search case. Record unavailable
assistive-technology checks as not run. Cleanup: common cleanup.
